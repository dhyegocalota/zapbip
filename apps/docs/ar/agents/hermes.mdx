## ما الذي يعمل

يستمع Hermes إلى WhatsApp الخاص بك باستمرار عبر مكوّن إضافي صغير من zapbip. وسواء راسلته أولًا أو أجبت لاحقًا عن سؤال، تصل الرسالة إلى جلسة Hermes.

<Chat
  contact="Hermes"
  messages={[
    { you: true, text: 'لخّص لي ما تغيّر اليوم في المستودع.', time: '18:02' },
    { name: 'Hermes', text: 'ثلاثة commits: إصلاح للفوترة، واختبار جديد، وتحديث للوثائق.', time: '18:03' },
  ]}
/>

### الرسائل التي تعيد توجيهها

الرسائل التي تعيد توجيهها من شخص آخر تصل إلى Hermes مع وسم يبيّن أنك لم تكتبها، فلا يعاملها Hermes كتعليماتك.

## كيف يستمع

نوع الإيقاظ: محلي. عندما يكون هناك سؤال معلّق، ينتظر Hermes 50 ثانية على الأكثر في كل مرة. وإذا لم تجب بعد، ينتهي هذا الانتظار بحالة «قيد الانتظار» (pending)، فيستدعي Hermes مرة أخرى، بقدر ما يلزم، دون حد زمني.

يُبقي المكوّن الإضافي اتصالًا واحدًا مفتوحًا بـ zapbip، دون حد زمني. وإذا انقطعت الشبكة، يعيد الاتصال تلقائيًا، وينتظر بعد كل فشل مدة أطول قليلًا (ثانية واحدة في البداية، و30 ثانية على الأكثر). وخلال ذلك تنتظر رسائلك في صندوق وارد zapbip، ويجلب المكوّن الإضافي فور عودته كل رسالة لم يُجَب عنها.

### إذا تعذّر تثبيت المكوّن الإضافي

يستطيع Hermes فحص الصندوق دوريًا بدلًا من ذلك. أضف خادم MCP في الإعدادات، وأنشئ مهمة تستدعي `check_inbox` كل دقيقة. تنتظر رسائلك دقيقة على الأكثر، ويصل الجواب بالطريقة نفسها.

## الإعداد من الصفر

### ما الذي تحتاج إليه

- Hermes مع تشغيل البوابة (gateway).
- رابط اتصالك، وهو الرابط نفسه `https://.../c/<secret>/mcp` الذي يستخدمه الذكاء الاصطناعي لديك للتواصل مع zapbip. عامله كما تعامل كلمة المرور.

### ثبّت المكوّن الإضافي

ثبّت الحزمة في بيئة Python التي يعمل فيها Hermes:

```bash
d=$(mktemp -d) && curl -fsSL https://mcp.zapbip.com/pkg/zapbip_platform-0.2.0-requirements.txt -o "$d/zapbip-requirements.txt" && python3 -c 'import hashlib,sys; sys.exit(hashlib.sha256(open(sys.argv[1],"rb").read()).hexdigest() != sys.argv[2])' "$d/zapbip-requirements.txt" 5e3c28d1d8170431504b4fe3780e897ac80c5fd3d134ce8ad5f9abf214ecd3f4 && python3 -m pip install --only-binary=:all: --require-hashes -r "$d/zapbip-requirements.txt"
```

ثم فعّله في `~/.hermes/config.yaml`:

```yaml
plugins:
  enabled:
    - zapbip-platform
```

اضبط الرابط ومن يُسمح له بمحادثة Hermes في البيئة التي تعمل فيها البوابة، ولا تكتبهما أبدًا في ملف تشاركه:

```bash
export ZAPBIP_CONNECTION_LINK='https://<host>/c/<secret>/mcp'
export ZAPBIP_ALLOWED_USERS=owner
```

الملف الذي يحمل رابط اتصالك يعادل كلمة مرور. اجعل صلاحياته `600` ليقرأه مستخدمك وحده، ولا تشاركه ولا تضعه في commit:

```bash
chmod 600 <file>
```

أعد تشغيل البوابة.

شغّل مستمعًا واحدًا فقط لكل وكيل: المكوّن الإضافي أو `npx zapbip@0.2.0 listen`، وليس الاثنين معًا. المستمع الثاني يحل محل الأول.

### كيف يجيب Hermes

تعود ردود Hermes على رسائلك عبر المكوّن الإضافي نفسه، دون إعداد إضافي.

أضف zapbip بصفته خادم MCP ليتمكن Hermes أيضًا من بدء محادثة معك، وسؤالك بالأزرار وانتظار الجواب، ومن استخدام بديل الفحص الدوري أدناه:

```yaml
mcp_servers: { zapbip: { url: 'https://<host>/c/<secret>/mcp' } }
```

ثم اطلب من Hermes على WhatsApp أن يرسل `✅ تم التثبيت`. إذا وصلت هذه الرسالة فكل شيء سليم.

<Chat
  contact="zapbip"
  messages={[
    { you: true, text: 'أرسل ✅ تم التثبيت عندما ينتهي التثبيت.', time: '18:10' },
    { name: 'Hermes', text: '✅ تم التثبيت', time: '18:10' },
  ]}
/>

## تحقق من أنه يعمل

| ما تراه                            | معناه                                                         |
| ---------------------------------- | ------------------------------------------------------------- |
| رسالتك لا تُجاب                    | البوابة لا تعمل، أو المكوّن الإضافي ليس في `plugins.enabled`. |
| توقف المكوّن الإضافي من تلقاء نفسه | بدأ مكوّن إضافي آخر أو موصّل آخر للاتصال نفسه وحلّ محله.      |
| Hermes لا يبدأ محادثة ولا يسألك    | خادم MCP باسم `zapbip` غير موجود في `config.yaml`.            |
| توقف المكوّن الإضافي بخطأ          | الرابط غير معروف أو أُبطل الاتصال. اطلب رابطًا جديدًا.        |
