---
title: 'connect_agent'
description: 'WhatsApp에서 소유자가 허용한 뒤 새 에이전트를 연결합니다.'
---

새 에이전트를 이름으로 이 계정에 연결합니다. 소유자에게는 호출한 에이전트의 이름으로 WhatsApp에서 묻고, 호출은 답을 기다립니다. `새 에이전트` 명령어와 같은 유스케이스를 실행하므로, 이름 규칙, 8개 에이전트 한도, 설치 링크가 같습니다. [AI에게 zapbip을 맡기세요](/ko/features/let-your-ai-manage-zapbip)를 참고하세요.

## 입력

| 필드   | 타입   | 비고                                                                    |
| ------ | ------ | ----------------------------------------------------------------------- |
| `name` | string | 명령어처럼 단순화됩니다. 소문자, 악센트 없음, 공백은 하이픈, 최대 20자. |

## 질문

세 개의 버튼 **Allow**, **Allow, send to agent**, **Deny**가 질문 끝의 짧은 참조와 함께 표시됩니다. 호출은 최대 50초 기다립니다. 버튼으로 답한 것만 유효하며, 입력한 텍스트는 Deny로 처리됩니다. Deny와 무응답은 아무것도 바꾸지 않고, 기다린 뒤의 답도 아무것도 바꾸지 않습니다. 이때 같은 요청은 10분 동안 거부됩니다(`cooling_down`).

## 출력

`{ "status": "applied" | "denied" | "timed_out" | "refused", "agent": string | null, "reason": string | null, "install_prompt": string | null }`.

- `applied`: 에이전트가 연결되었습니다. **Allow** 뒤에는 설치 링크가 WhatsApp으로 소유자에게 갔고 `install_prompt`는 `null`입니다. **Allow, send to agent** 뒤에는 `install_prompt`에 새 에이전트에 붙여넣을 두 줄이 들어 있습니다. 링크나 키가 도구 결과에 도달하는 유일한 경로입니다.
- `denied`와 `timed_out`: 아무것도 바뀌지 않았습니다.
- `refused`: `reason`은 `invalid_name`, `reserved_name`, `name_taken`, `limit_reached`, `cooling_down`, `window_closed`, `send_failed`, `suspended`, `waitlisted` 중 하나입니다. 올바르지 않거나 예약된 이름은 소유자에게 묻기 전에 거부됩니다. 링크를 보낼 수 없으면 새 연결은 다시 폐기됩니다.

작업을 수행하는 호출(`connect_agent`, [revoke_agent](/ko/mcp-reference/revoke-agent), [sign_in_link](/ko/mcp-reference/sign-in-link))은 연결당 1분에 최대 3번입니다. 그다음 호출은 `rate_limited`로 시작하는 오류가 됩니다.
