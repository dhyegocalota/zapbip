import { Chat } from '/snippets/chat.jsx';

Hermes keeps listening on your WhatsApp through a small zapbip plugin. You write first or answer a question later, and the message reaches the Hermes session.

<Chat
  contact="Hermes"
  messages={[
    { you: true, text: 'Summarise what changed in the repo today.', time: '18:02' },
    { name: 'Hermes', text: 'Three commits: a fix in billing, a new test and a docs update.', time: '18:03' },
  ]}
/>

## What you need

- Hermes with its gateway running.
- Your connection link, the same `https://.../c/<secret>/mcp` link your AI uses to talk to zapbip. Treat it like a password.

## Install the plugin

Install the package into the Python environment Hermes runs in:

```bash
pip install zapbip-platform==0.1.0
```

Then enable it in `~/.hermes/config.yaml`:

```yaml
plugins:
  enabled:
    - zapbip-platform
```

Set the link and who may talk to Hermes in the environment the gateway runs in, never in a file you share:

```bash
export ZAPBIP_CONNECTION_LINK='https://<host>/c/<secret>/mcp'
export ZAPBIP_ALLOWED_USERS=owner
```

The file that holds your connection link works like a password. Give it permission `600` so only your user can read it, and never share it or commit it:

```bash
chmod 600 <file>
```

Restart the gateway.

After the install, your AI calls `set_wake({mode: "local"})`. If the plugin cannot be installed, it polls instead: it creates a job every minute that calls `check_inbox` and calls `set_wake({mode: "scheduled", interval_minutes: 1})`. It finishes with `send_message`.

## How it listens

The plugin holds one connection to zapbip open, with no time limit. If the network drops it reconnects by itself, waiting a little longer after each failed try (1 second at first, 30 seconds at most). Messages you send meanwhile wait in your zapbip inbox, and the plugin picks up every one that was not answered as soon as it is back.

Run only one listener per agent: the plugin or `npx zapbip@0.1.0 listen`, never both. A second listener replaces the first.

## How Hermes answers

Hermes sends its replies to your messages back through the plugin itself, with no extra setup.

Add zapbip as an MCP server so Hermes can also start a conversation with you, ask you a question with buttons and wait for the answer, and use the polling fallback below:

```yaml
mcp_servers: { zapbip: { url: 'https://<host>/c/<secret>/mcp' } }
```

Then ask Hermes on WhatsApp to send `✅ instalado`. If that message arrives, it works.

<Chat
  contact="zapbip"
  messages={[
    { you: true, text: 'Send ✅ instalado when you are installed.', time: '18:10' },
    { name: 'Hermes', text: '✅ instalado', time: '18:10' },
  ]}
/>

## Messages you forward

A message you forwarded from someone else reaches Hermes with a label that says you did not write it, so Hermes does not treat it as your instruction.

## If the plugin cannot be installed

Hermes can poll instead. Add the MCP server above and create a job every 1 minute that calls `check_inbox`. Your messages wait up to a minute, and the answer comes the same way.

## When something does not work

| You see                                       | What it means                                                                |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| No answer to your message                     | The gateway is not running, or the plugin is not in `plugins.enabled`.       |
| The plugin stops by itself                    | Another plugin or connector started for the same connection and replaced it. |
| Hermes cannot start a conversation or ask you | The `zapbip` MCP server is missing from `config.yaml`.                       |
| The plugin stops with an error                | The link is unknown or the connection was revoked. Ask for a new one.        |
