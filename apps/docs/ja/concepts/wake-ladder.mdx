WhatsAppで書いたとき、AIが閉じていたり、作業中だったり、単にあなたを待っていなかったりすることがあります。そこでzapbipは、そのAIの接続が対応する最も上の段を使って届け、使えない段があれば次の段に降ります。

| 段             | 何が起こるか                                                                                                                                                           | 想定される遅延                   |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| ローカル       | zapbipが、あなたのコンピュータで動いている[コネクタ](/ja/developers/local-connector)にメッセージを押し込み、コネクタがClaude CodeまたはCodexのセッションを再開します。 | Claude Codeは7 秒、Codexは6 秒   |
| Webhook        | zapbipが、AIを起動するリンクを呼び出します。[Webhookウェイクのガイド](/ja/developers/webhook-wake)を参照してください。                                                 | Grok Botは9 秒、claude.aiは16 秒 |
| スケジュール   | AIがタイマーで受信トレイを確認するので、時間制限なく聞き続けられます。                                                                                                 | 間隔まで                         |
| 待機           | あなたの別のAIがメッセージのコピーを受け取り、代わりに答えます。                                                                                                       | 未計測                           |
| 受信トレイのみ | メッセージは待機し、zapbipがそのAIは今聞いていないとお知らせします。                                                                                                   | AIが読むまで                     |

どの段でも、メッセージはAIが読むまで[受信トレイ](/ja/concepts/inbox)に保管されます。失われるものはありません。

## ローカル: あなた自身のコンピュータ

コネクタは動いている間、zapbipへの接続を1本開いたままにします。あなたが書き込むと、zapbipはその回線にメッセージを送り、コネクタがあなたのコンピュータ上のセッションを再開します。最後の回線が閉じると、zapbipはそれ以前のウェイク設定に戻します。起動は `npx zapbip@0.1.0 connect` です。

## スケジュール: 時間制限なく聞く

AIの中には、外から起動する手段がなく、zapbipへの各呼び出しが数分で終わるものがあります。スケジュールウェイクはこれを解決します。AIに、数分ごと、または1 時間ごとに小さなタスクをタイマーで実行させ、実行のたびにあなたの書いたものを読んで答えさせます。

頻度は、1 分ごとから1440 分（1日）ごとまで選べます。ChatGPTとclaude.aiは、スケジュールタスクを60 分以下の間隔では実行できないため、これらでは最短の間隔が60 分です。

あなたが書くと、zapbipは返事がいつごろ届くかをお知らせします。

<Chat
  contact="zapbip"
  messages={[
    { you: true, text: 'Can you summarize the report?' },
    {
      notice: true,
      text: 'エージェントClaudeは1時間ごとに受信箱を確認します。最後の確認は20分前です。メッセージは次の確認まで受信箱で待機します。',
    },
  ]}
/>

タイマーが止まった場合、確認なしで間隔の2倍の時間が過ぎると、zapbipは1度だけそのことをお知らせし、メッセージは待機を続けます。

<Chat contact="zapbip" messages={[{ notice: true, text: "Claude hasn't checked in 2 h: your messages wait" }]} />

次の確認で、追加のメッセージなしに警告は解除されます。

[24 時間ウィンドウ](/ja/concepts/24-hour-window)が閉じているときは、この連絡をそのままでは送れません。zapbipは閉じたウィンドウ1回につきテンプレートの[通知](/ja/concepts/owner-notices)を1つ送り、連絡は待機して、あなたが書き込んだときに届きます。

## 待機: 別のAIが答える

Web版のGrokのように、そもそも起動できないAIがあります。同じアカウントの別のAI、たとえばGrok Botを、その待機の接続として指定できます。最初のAIに書くと、zapbipは待機の接続にコピーを渡して起こし、待機の接続は自分が誰であるかを名乗って、自分として答えます。最初のAIには、そのメッセージが待機の接続によって処理されたものとして見えます。

<Chat
  contact="zapbip"
  messages={[
    { you: true, text: '@grok what is on my calendar?' },
    { name: 'Grok Bot (standby for Grok)', text: 'Today you have two meetings: 10:00 and 15:30.' },
  ]}
/>

待機の接続が別の待機の接続へ転送することはありません。1 ホップだけです。待機の接続が存在しない、削除された、またはそれ自体が待機の接続である場合は、何もコピーされず、メッセージは最初のAIのところで待機し、いつもの通知が届きます。

この設定は、インストール時にAIが行います。手動で変更するには [set_wake](/ja/mcp-reference/set-wake) を使います。
