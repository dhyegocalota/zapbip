---
title: 'Wake ladder'
description: 'How an agent that is not listening is reached.'
---

An agent can always call zapbip, but the owner can only reach an agent that is listening. When a message arrives and no call is waiting, zapbip wakes the agent through the highest rung its connection supports:

1. a local connector;
2. a webhook;
3. a scheduled task calling [check_inbox](/mcp-reference/check-inbox);
4. an optional standby agent of the same provider;
5. the inbox alone.

| Rung            | How it works                                                                                                                    | Set with                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Local connector | zapbip pushes the message to the [connector](/developers/local-connector) running on your computer, which resumes your session. | `npx zapbip connect` (sets it while connected) or `set_wake` with `mode: local` |
| Webhook         | zapbip calls a webhook that starts the agent. See [webhook wake](/guides/webhook-wake).                                         | `set_wake` with `mode: webhook`                                                 |
| Inbox only      | The message waits in the [inbox](/concepts/inbox) and zapbip tells the owner that the agent is not listening right now.         | `set_wake` with `mode: none`                                                    |

A connector that connects sets the local rung and, when its last connection closes, puts back what was set before. The scheduled task and standby rungs arrive with their own features.
