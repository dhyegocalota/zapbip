---
title: 'connect_agent'
description: 'Connecte un nouvel agent après l’accord du propriétaire sur WhatsApp.'
---

Connecte un nouvel agent à ce compte, par son nom. Le propriétaire est interrogé sur WhatsApp, au nom de l’agent appelant, et l’appel attend la réponse. Il exécute le même cas d’usage que la commande `nouvel agent` : les règles de nom, la limite de 8 agents et le lien d’installation sont donc les mêmes. Voir [Laissez votre IA gérer zapbip](/fr/features/let-your-ai-manage-zapbip).

## Entrée

| Champ  | Type   | Remarques                                                                                                    |
| ------ | ------ | ------------------------------------------------------------------------------------------------------------ |
| `name` | string | Simplifié comme pour la commande : minuscules, sans accents, tirets pour les espaces, jusqu’à 20 caractères. |

## La question

Trois boutons : **Allow**, **Allow, send to agent** et **Deny**, avec une courte référence à la fin de la question. L’appel attend jusqu’à 50 secondes. Seul un appui sur un bouton compte : le texte saisi est lu comme un Deny. Deny et le silence ne changent rien, et un appui après l’attente ne change rien non plus ; la même demande est alors refusée (`cooling_down`) pendant 10 minutes.

## Sortie

`{ "status": "applied" | "denied" | "timed_out" | "refused", "agent": string | null, "reason": string | null, "install_prompt": string | null }`.

- `applied` : l’agent a été connecté. Après **Allow**, le lien d’installation est allé au propriétaire sur WhatsApp et `install_prompt` vaut `null`. Après **Allow, send to agent**, `install_prompt` contient les deux lignes à coller dans le nouvel agent. C’est la seule façon pour un lien ou une clé d’arriver dans le résultat d’un outil.
- `denied` et `timed_out` : rien n’a changé.
- `refused` : `reason` vaut `invalid_name`, `reserved_name`, `name_taken`, `limit_reached`, `cooling_down`, `window_closed`, `send_failed`, `suspended` ou `waitlisted`. Un nom invalide ou réservé est refusé avant que le propriétaire soit interrogé. Quand le lien ne peut pas être envoyé, la nouvelle connexion est de nouveau révoquée.

Au plus 3 appels qui agissent (`connect_agent`, [revoke_agent](/fr/mcp-reference/revoke-agent) et [sign_in_link](/fr/mcp-reference/sign-in-link)) par minute et par connexion ; le suivant est une erreur qui commence par `rate_limited`.
