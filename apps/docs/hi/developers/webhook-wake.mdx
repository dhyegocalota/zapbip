Webhook वेक, [वेक लैडर](/hi/concepts/wake-ladder) का दूसरा स्तर है। जब ओनर WhatsApp पर लिखता है और एजेंट नहीं सुन रहा होता, तो zapbip एक लिंक कॉल करता है जो उसे शुरू करता है। जिन क्लाइंट में यह सपोर्ट है, उनके लिए इंस्टॉल फ़्लो इसे सेट कर देता है; यह पेज बताता है कि zapbip क्या भेजता है और इसे हाथ से कैसे सेट करें।

फिर एजेंट [check_inbox](/hi/mcp-reference/check-inbox) या [get_messages](/hi/mcp-reference/get-messages) से संदेश पढ़कर जवाब देता है। लिंक [set_wake](/hi/mcp-reference/set-wake) से सेव किया जाता है।

कॉल में आपका कोई टेक्स्ट नहीं होता: उसकी बॉडी हमेशा `{"event":"inbox_has_messages"}` होती है। एक साथ आए संदेश एक ही वेक साझा करते हैं, जो पहले संदेश के कुछ सेकंड बाद भेजा जाता है।

## Grok Bot रूटीन

webhook ट्रिगर वाला एक रूटीन बनाएँ, फिर उसे सेव करें:

```json
{ "mode": "webhook", "url": "https://api2.cursor.sh/automations/webhook/<routine-id>", "token": "<token>" }
```

zapbip `Authorization: Bearer <token>` भेजता है।

## claude.ai शेड्यूल्ड टास्क

API ट्रिगर वाला एक शेड्यूल्ड टास्क बनाएँ, फिर उसे सेव करें:

```json
{ "mode": "webhook", "url": "https://api.anthropic.com/v1/claude_code/routines/<trigger-id>/fire", "token": "<token>" }
```

zapbip `Authorization: Bearer <token>` और रूटीन के हेडर भेजता है।

## आपकी अपनी सर्विस

कोई भी सार्वजनिक `https` होस्ट चलेगा। टोकन आपकी साइनिंग की है, कम से कम 32 अक्षरों की, और यह कभी भेजी नहीं जाती। हर अनुरोध में `X-Zapbip-Timestamp` (Unix सेकंड) और `X-Zapbip-Signature` होता है, यानी `sha256=` के बाद `<timestamp>.<body>` का hex HMAC-SHA256। 300 सेकंड से पुराना टाइमस्टैम्प ठुकरा दें।

```json
{ "mode": "webhook", "url": "https://api2.cursor.sh/automations/webhook/<routine-id>", "token": "<token>" }
```

## जब वेक फ़ेल हो

- `408`, `425`, `429`, `5xx`, टाइमआउट या नेटवर्क की गड़बड़ी पर 5 कोशिशों तक दोबारा कोशिश होती है, 5, 10, 20 और 40 सेकंड रुककर, और `429` और `503` पर `Retry-After` का पालन करते हुए, 60 सेकंड तक।
- रीडायरेक्ट और बाकी `4xx` जवाब तुरंत ठुकरा दिए जाते हैं और दोबारा कोशिश नहीं होती।
- जब कोई वेक ठुकराया जाता है या कोशिशें खत्म हो जाती हैं, तो आपको WhatsApp पर एक सूचना मिलती है कि संदेश इनबॉक्स में इंतज़ार कर रहा है, और कनेक्शन `failing` मार्क हो जाता है। टारगेट ठीक करने के लिए [set_wake](/hi/mcp-reference/set-wake) फिर से कॉल करें; अगला डिलीवर हुआ वेक उसे वापस `active` कर देता है।
- अगर एजेंट वेक भेजे जाने से पहले ही संदेश पढ़ ले, तो कोई अनुरोध नहीं भेजा जाता।
